# Power BI — Decoding Customer Value

This folder contains the implementation specification for the production Power BI version of the Founder Dashboard.

## Data source

Use `data/customer_features.csv` as the primary table. It is the engineered customer-level table produced by the existing Python pipeline.

**Grain:** one row per customer.

Key fields:
- `Customer ID`
- `Purchase Amount (USD)`
- `Location`
- `Category`
- `Season`
- `Review Rating`
- `Previous Purchases`
- `est_annual_orders`
- `est_annual_value`
- `lifetime_value_proxy`
- `promo_dependency_score`
- `is_promo_dependent`
- `is_organic_high_value`
- `satisfaction_score`
- `is_at_risk_dissatisfied`
- `customer_value_score`
- `value_tier`
- `category_role`

## Dashboard architecture

### Page 1 — Executive Customer Value

KPI cards:
1. Customers
2. Annualized Customer Value
3. Average Customer Value Score
4. Promo Dependency %
5. Organic High-Value Customers %
6. Average Satisfaction

Visuals:
- Customer Pyramid: customers and annualized value by `value_tier`
- Annualized Value vs. Tenure scatter, sized by customer count and colored by `value_tier`
- Promo Dependency vs. Retention clustered column chart
- Value-tier composition 100% stacked bar

Slicers:
- Gender
- Category
- Season
- Location
- Subscription Status
- Value Tier
- Promo Dependency

### Page 2 — Promo Economics

- Promo-dependent vs. organic customers by value tier
- Average annualized value by promo dependency
- Average tenure by promo dependency
- Promo dependency distribution
- Organic high-value customer count and share

Decision question: where can discounts be reduced without materially damaging customer value?

### Page 3 — Geographic Opportunity

- Scatter: average spend vs. promo reliance by state
- Bubble size: customer count
- Opportunity classification: Organic High-Traction / Underleveraged / Discount-Propped / Low-Priority
- Ranked state table with spend, promo reliance, value score and customer count

Decision question: where should acquisition and retention investment move next?

### Page 4 — Category & Customer Profile

- Category role by category
- Average tenure by category
- Average annualized value by category
- Customer value tier by category
- Demographic profile of Platinum/Gold customers

Decision question: which categories are entry points and which categories support retention?

## Interaction design

Enable cross-filtering between all charts. Use report-page tooltips for state and value-tier details. Add drill-through from `value_tier` to a Customer Detail page using `Customer ID`, `Item Purchased`, `Category`, `Location`, `Previous Purchases`, `est_annual_value`, `customer_value_score`, `value_tier`, and promo flags.

Use bookmarks for:
- Executive view
- Promo strategy view
- Geographic opportunity view

## DAX

The recommended measures are in `CustomerValue_DAX.dax`.

## Theme

`customer_value_theme.json` provides a restrained executive palette consistent with the existing dashboard artifact.

## Publishing

1. Open Power BI Desktop.
2. Import `data/customer_features.csv`.
3. Set the model to a single customer-grain table.
4. Add the measures from `CustomerValue_DAX.dax`.
5. Apply `customer_value_theme.json`.
6. Build the four report pages described above.
7. Publish to a Power BI workspace.
8. In Power BI Service, use **File → Embed report → Publish to web (public)** only if the data is approved for public disclosure.
9. Paste the resulting public report URL into the `POWER_BI_LIVE_URL` marker in the root README.

### Important limitation

A genuine Power BI Service report URL is generated by Microsoft's Power BI Service after a report is published from an authenticated Power BI account. The GitHub connector available to this project can modify the repository but cannot authenticate to or publish into a Power BI tenant. This repository therefore does not fabricate a Power BI URL. The model, measures, theme, page specification and source data are prepared here so the final publish step is deterministic and auditable.
